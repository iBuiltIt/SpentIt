# Experimental QIF profile v3

Last updated: 2026-10-27

Implementation contract for the accepted [durable import milestone](009-durable-import-milestone.md). This deliberately bounded profile is not general QIF compatibility. The field identifiers and transfer notation were checked against [GnuCash's QIF notes](https://raw.githubusercontent.com/Gnucash/gnucash/stable/gnucash/import-export/qif-imp/file-format.txt); restrictions below are SpentIt choices. No private exports were inspected.

- UTF-8, optionally beginning with a BOM; LF or CRLF; no embedded NUL, lone CR or other ASCII control characters except tab in text fields. Invalid encoding blocks the file. No decoding substitution.
- An optional initial `!Type:Bank`, `!Type:Cash` or `!Type:CCard` header selects ordinary monetary records. Headerless banking records support the synthetic Wise shape. Named account lists and repeated ordinary sections are handled by the account-section extension below; other headers remain unsupported. Blank lines are rejected. A final line need not end with a newline.
- A record ends with a line containing only `^`. Every record needs exactly one `D` date and `T` amount. Missing terminators, empty records and repeated singleton fields block the record. An empty file is an error.
- Dates are one/two-digit day and month separated by `/`, with a four-digit year in 0001–9999. An explicit DMY or MDY profile is mandatory. Gregorian calendar validation rejects impossible dates. Normalized dates use YYYY-MM-DD without timezone conversion.
- Money uses the engine's strict ASCII decimal grammar and the supplied account currency definition. No grouping separators, exponent, whitespace, rounding or inferred currency. Original imported totals are retained.
- Optional singleton `P`, `M`, `N`, `L`, `C` fields represent payee, memo, reference, category and cleared status. `C` supports empty, `*`, `c`, `X`, `R`; budget/reminder markers are blocked. Addresses (`A`, at most six lines) are evidence-only. Unknown fields, including `U` and percentage splits, block rather than override a total or silently lose semantics.
- Splits repeat optional `S` category, optional `E` memo, then required `$` amount, in that order. Missing `S` supports Wise-shaped exports. A new group begins after `$`; repeated `S` or `E`, fields out of order and incomplete groups block. Parent fields must precede split fields. Splits sum exactly to `T`; no balancing repair. Without splits, one allocation uses `L` and `M`. With splits, `L` must be empty or the literal `--Split--`; another parent category is ambiguous and blocked. Mixed-sign and zero splits are preserved.
- `L[Account]` and `S[Account]` retain explicit transfer destinations for [account resolution](../doc/qif-transfers.md). The bracket contents must be nonempty and not all spaces, with no nested brackets, tabs, newlines or class separators. Malformed brackets block. No account is inferred or created by parsing. One `/Class` suffix is accepted for an ordinary category or bracketed transfer destination. The nonempty class is retained separately as source metadata and displayed read-only; it does not create a category, account or report classification. Empty/space-only class names and class strings containing `/`, `|`, brackets or tabs are blocked. Investment `|` combinations remain unsupported. Ordinary category text is retained without a hierarchy model.
- Limits: 64 MiB source, 200,000 records, 1 MiB per record including terminator/newlines, 64 KiB field value, 1,000 allocations per record. Over-limit results are explicitly inadmissible for ingestion. One first diagnostic per record bounds error growth; file-level diagnostics stop parsing. Byte offsets and record ordinals identify errors without putting financial values in messages.

A parse result does not commit anything. Source bytes remain the caller's immutable evidence; record byte ranges reference those exact bytes, including delimiters. Invalid records have diagnostics and no validated transaction. Valid records from an otherwise blocked file are never permission for partial commit. Application persistence and correction decisions are separate responsibilities.

The parser exposes an optional original amount, explicit source currency definition, and source-allocation fields whose amounts may be unavailable. Every syntactically complete split keeps its original position, category, memo and class even when `$` is invalid; no zero amount or shifted ordinal stands in for unknown evidence. Parsed allocations with known amounts are evidence only until exact transaction validation succeeds. A missing/invalid parent total still preserves the unsplit category/transfer destination.

Repairability requires intact record/split structure and only date, missing required date/total, exact-amount, or split-total errors. Unknown/repeated fields, encoding errors, malformed destinations and incomplete or ambiguous split grouping remain blocked. A repair must supply valid effective money and allocations, preserve transfer intent and source associations, and explicitly resolve duplicate disposition. Original unavailable money stays unavailable. The [milestone follow-up](009-durable-import-milestone.md#accepted-ordinary-qif-and-amount-repair-follow-up--2026-10-26) records accepted scope and whole-import UX; [status](../doc/status.md#ordinary-qif-and-unknown-amount-repair-checkpoint--2026-10-26) distinguishes implementation from verification.

## Account-section extension — 2026-10-26

The [whole-source account contract](../doc/qif-account-imports.md#accepted-source-envelope) specifies supported `!Account` lists, repeated ordinary sections, metadata fields, limits and refusal behavior. Each account's records reuse this ordinary grammar with explicit currency and date order. This does not admit investment or catalog sections, infer self-account opening records, or alter category/class and unknown-original repair invariants. Point 1 schemas 16/17 retained the source once and associated account drafts with stable source-account indices. The 2026-10-27 statement checkpoint used schemas 18/19, kept this QIF grammar, and added shared source-occurrence facts. Point 4 new documents use schemas 20/21 and reject 18 and 19 without migration. See the [statement profile](003-ofx-profile.md) and [account commands](002-accounts-money-splits.md#applied-account-management-checkpoint--2026-10-27).
